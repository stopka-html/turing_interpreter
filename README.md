# Тюрінговий калькулятор

Веб-симулятор детермінованої однострічкової машини Тюрінга. Задаєте таблицю переходів і вхідне слово, а машина виконує програму. Кожен такт видно на стрічці, а команда, яка зараз виконується, підсвічується в таблиці.

Це навчальний проєкт з дисципліни «Технологія створення програмних продуктів» (ЧНУ ім. Ю. Федьковича).

![Іконка](static/icons/icon-192.png)

## Можливості

- **Редактор таблиці переходів.** Стани й символи алфавіту можна додавати та видаляти прямо в таблиці.
- **Покрокове виконання.** Є пауза, зупинка, кнопка «До кінця» та регулятор швидкості. Протокол переходів можна зберегти в текстовий файл.
- **Підсвічування в таблиці.** Команда поточного такту підсвічується жовтим. Клітинка, для якої не знайшлося правила, підсвічується рожевим.
- **Готові приклади:** додавання, віднімання, множення й порівняння унарних чисел, подвоєння, інкремент та інверсія двійкового числа.
- **Збереження програми.** Таблиця зберігається у файл JSON і відкривається з нього. Крім того, вона автоматично зберігається в браузері.
- **Вбудована довідка** про формат команд.
- **Робота без інтернету (PWA).** Застосунок кешується в браузері, тож його можна встановити й запускати офлайн.

## Як записується програма

Таблиця має вигляд `{стан: {символ: команда}}`. Команда складається з трьох частин: символ, який треба записати, новий стан і напрям руху головки (`L`, `R` або `N`). Наприклад, `1q0R` означає: записати `1`, перейти в `q0`, зсунутися праворуч.

- `&` — порожній символ.
- `q*` — фінальний стан.
- Порожня клітинка означає, що правила немає.

```json
{
  "q0": { "1": "1q0R", "+": "1q1R" },
  "q1": { "1": "1q1R", "&": "&q2L" },
  "q2": { "1": "&q*N" }
}
```

Машина стартує в стані `q0` на першому символі слова. Інший стан чи інше положення головки задаються позначкою в апострофах: `11'q0'+11`.

## Запуск локально

Потрібен Python 3.10 або новіший.

```bash
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
python app.py                     # http://localhost:5500, перезавантажується при змінах
# або без livereload:
flask --app app run               # http://localhost:5000
```

## Як влаштовано

| Файл | Призначення |
|---|---|
| `turing.py` | Рушій машини Тюрінга на Python: перевірка таблиці, виконання, журнал тактів. |
| `static/turing.js` | Той самий рушій, перенесений на JavaScript. Завдяки йому програми виконуються в браузері. |
| `app.py` | Сервер на Flask: сторінка, `GET /examples`, `POST /run`, `/sw.js`. |
| `static/script_index.js` | Інтерфейс: редактор таблиці, програвач тактів, меню, приклади. |
| `static/sw.js` | Service worker, який кешує застосунок для роботи офлайн. |
| `static/manifest.json` | Маніфест PWA з назвою, кольорами та іконками. |
| `examples/*.json` | Готові приклади програм. |
| `build_static.py` | Збирає статичну копію сайту для GitHub Pages. |
| `tests/` | Автоматичні тести. |

**Хто виконує програму.** Програми з лімітом до 10 000 тактів виконуються прямо в браузері. Довші запуски, до 100 000 тактів, браузер відправляє на сервер (`POST /run`). Якщо сервер недоступний, наприклад офлайн або на GitHub Pages, браузер виконує програму сам.

**Синхронізація рушіїв.** `turing.py` і `turing.js` мають давати однакові результати й однакові повідомлення про помилки. Тому зміни в одному рушії треба вносити й в інший.

**Оновлення кешу.** Коли інтернет є, файли завжди беруться з мережі, і кеш оновлюється автоматично. Якщо змінюється список кешованих файлів у `static/sw.js`, треба збільшити `VERSION`.

## Тести

```bash
python -m unittest discover -s tests -v
```

Тести перевіряють три речі:

- **рушій `turing.py`:** усі приклади, статуси зупинки, журнал тактів і повідомлення про помилки;
- **API сервера:** `/run`, `/examples` і `/sw.js`;
- **відповідність `static/turing.js` рушію `turing.py`** на прикладах, помилкових таблицях і 300 випадкових програмах. Для цього потрібен Node.js; якщо його немає, тест пропускається.

На GitHub тести запускаються автоматично після кожного пушу (`.github/workflows/tests.yml`).

## Публікація на GitHub Pages

Після кожного пушу в `main` workflow `.github/workflows/pages.yml` збирає статичну копію (`python build_static.py`) і публікує її.

Перед першим запуском потрібно один раз увімкнути Pages: **Settings → Pages → Build and deployment → Source: GitHub Actions**. Після цього сайт буде доступний за адресою `https://stopka-html.github.io/turing_interpreter/`.

На GitHub Pages немає сервера, тому всі програми виконуються в браузері.

Статичну копію можна зібрати й переглянути локально:

```bash
python build_static.py dist
python -m http.server -d dist
```

Офлайн-режим і встановлення працюють лише через HTTPS або на `localhost`.
